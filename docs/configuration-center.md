# 配置中心

管理入口：`/admin/configuration`。首次设置 `/admin/setup` 复用相同配置接口，完成状态由后端计算。

## 分类与保存

| 分类 | 内容 |
| --- | --- |
| 品牌与身份 | 产品名称、Logo、公开地址、邮箱域、Key 前缀、客户端导出 |
| 系统设置 | 业务时区、使用中心登录有效期、管理密钥、初始密码、推理配色 |
| 请求与账号 | 代理、重试、会话保持、账号切换、端口、镜像、日志 |
| 用量与额度 | 额度、模型倍率、推理倍率、用量采集 |
| 通知设置 | 企业微信 Webhook、发送计划、额度预警 |
| 数据与审计 | 账号备份、存储状态、审计记录 |

左侧分类默认展开，选择子项后右侧展示配置。表格按“配置项 → 生效方式 → 配置值”排列；生效方式居中，配置值左对齐。滚动只移动数据，表头和底部保存栏固定。

切换子项保留草稿；底部保存、撤销作用于全部分类。搜索可定位字段和独立操作，旧分类/子项链接仍可跳转。Logo、凭据、Webhook 和用量清零独立保存，其中破坏性操作需要确认。

控件范围与生效方式以服务端配置目录为准：

| 生效方式 | 行为 |
| --- | --- |
| `live` | 后续读取使用新值 |
| `accounts` | 经账号生命周期流程应用 |
| `quota` | Collector 发布快照后由 Gateway 执行 |
| `deployment` | 由目标部署流程应用 |

## 常用设置

- 新 Key 默认前缀为 `ccpa_`，仅影响新建或轮换；已有 Key 不改写。
- 客户端 Key 环境变量默认为 `CCPA_API_KEY`；已保存的名称优先。
- 使用中心登录有效期为 1–12 小时，可用小时、天和小数显示，接口保存整数秒。
- 会话亲和默认 1 小时，范围 30 秒至 30 天，支持秒、分钟、小时、天显示。
- 账号自动切换支持 `off`、`active`。

### 系统时区

`system.timezone` 统一控制页面时间、自然日/自然周、趋势与通知，默认 `Asia/Shanghai`。修改后 Collector 重启并重新归集周用量，原始时间戳不改写。

旧配置按系统、额度、通知时区的顺序迁入此键；原额度与通知时区不同的环境，应核对新发送时间。宿主机时区不变，容器使用 UTC，旧 `CPA_TIMEZONE` 不再生效。

### 额度与倍率

“活跃用户统计窗口”控制账号列表、Usage、自动切换刷新和通知中的滚动去重用户统计，单位为秒，默认 `900`（15 分钟），可配置为 60–86400 秒。修改后后续读取立即使用新窗口。

“额度”集中设置用户额度、官方额度查询和用量维护；模型倍率、推理倍率分别管理。倍率大于 1 时显示“高倍率”标记。

加权 Token 在新事件采集时按“模型倍率 × 推理强度倍率”写入，历史记录不重算。`gpt-6-astra` 默认 4 倍，其他已知模型及未匹配模型默认 1 倍。模型字段为空时才回退到 alias，匹配忽略大小写和首尾空格。

“保留修改后的额度”默认关闭，下周恢复组织默认额度；开启后保留个人额度。两种模式下周用量重新累计，临时追加额度在换周后失效。

### 企业微信通知

Webhook 独立保存，已保存地址仅展示 key 末四位；更换时输入框为空，清除地址会关闭通知。

通知 Worker 随部署启动；开关开启且 Webhook 已配置才自动发送。页面分别显示调度心跳、发送结果和下次发送时间。心跳超过 3 分钟未更新时隐藏下次发送时间；手动发送成功不代表调度正常。

报告包含完整统计时间、阈值，以及账号总数、配置窗口内活跃账号、正常/预警/耗尽/数据不可用/已停用数量。所有通知头部均展示完整使用中心地址；未设置公开应用地址时显示“未配置”。时间按系统时区转换，显示为 `YYYY-MM-DD HH:mm:ss`，不附加时区字样。

账号明细统一使用表格，列为账号、周额度已用、配置窗口内用户、剩余重置次数和下次周期重置。只使用账号常规周额度，不包含附加额度窗口或套餐分布。按当前周额度已用百分比从小到大排序，同值按账号名称自然排序，数据不可用的账号显示 `—` 并排在最后。状态同时覆盖已发布的账号容量结果：已停用 `⏸️`、服务停止 `⛔`、未授权或凭据不可用 `🔐`、额度过期/不可用 `⚪`、上游不允许 `🔴`、额度预留 `🟠`；这些非正常状态不会用旧额度覆盖，也不参与额度预警、耗尽、恢复和周期重置判断。

预警、耗尽、恢复和周期重置使用同一表格，单账号也保留完整列，并增加“变化”列展示事件及已知的前后用量。预警、耗尽和恢复事件仅展示本次涉及账号；周期重置事件确认后发送全量账号表。定时报告合并事件时仍保留全量汇总。通道测试使用通知类型和状态两列表格。

“下次周期重置”表示常规周额度窗口的重置时间；仅用量下降不判定为周期重置。定时漏发超过补发窗口不自动补发。单条消息上限为 4096 字节，超限报错。

Telegram 项目发布公告在发布工作站[单独配置](telegram-release.md)。

## 开发约定

接口以 [OpenAPI](../api/openapi.yaml) 为准。配置和加密秘密存于控制库，用量与会话存于用量库；生成的账号配置和 Gateway 快照不是人工配置入口。

完整凭据不进入 URL、持久化浏览器存储或普通查询缓存。一次性凭据关闭弹窗后清理；`/site-config.json` 只输出公开品牌、允许的邮箱域和客户端导出字段。

页面结构见 [ConfigurationPage](../frontend/src/ui/ConfigurationPage.tsx)，布局见[配置样式](../frontend/src/ui/configuration-page.css)和[控件宽度](../frontend/src/ui/configuration-layout.ts)。修改接口时同步生成类型、前后端实现、测试与 Preview fixture；验证流程见[开发指南](development.md)。

## 界面与通知语言

页面默认英文，可通过语言选择器切换简体中文。配置中心的 `system.language` 控制定时通知、额度预警、手动报告与通知测试的语言，默认为 `en`，也可保存为 `zh-CN`。报表下载跟随页面所选语言；业务时区仍由 `system.timezone` 单独控制。详见[多语言设计](internationalization.md)。
