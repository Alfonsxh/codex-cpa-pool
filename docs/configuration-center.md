# 配置中心

管理入口：`/admin/configuration`。首次设置 `/admin/setup` 复用相同配置接口，完成状态由后端计算。

## 分类与保存

| 分类 | 内容 |
| --- | --- |
| 品牌与身份 | 产品名称、Logo、公开地址、邮箱域、Key 前缀、客户端导出 |
| 系统设置 | 业务时区、使用中心登录有效期、管理密钥、初始密码、推理配色 |
| CPA 容器 | 请求与代理、容器参数、日志、端口与镜像、Codex Ticket 插件 |
| 请求与账号 | Gateway 推理强度上限、账号自动切换 |
| 用量与额度 | 额度、模型倍率、推理倍率、用量采集 |
| 通知设置 | 企业微信 Webhook、发送计划、额度预警 |
| 数据与审计 | 账号备份、存储状态、审计记录 |

左侧分类默认展开，选择子项后右侧展示配置。表格按“配置项 → 生效方式 → 配置值”排列；生效方式居中，配置值左对齐。滚动只移动数据，表头和底部保存栏固定。

切换子项保留草稿；底部保存、撤销作用于全部分类。搜索可定位字段和独立操作，旧分类/子项链接仍可跳转。Logo、凭据、Webhook 和用量清零独立保存，其中破坏性操作需要确认。

控件范围与生效方式以服务端配置目录为准：

| 生效方式 | 行为 |
| --- | --- |
| `live` | 后续读取使用新值 |
| `accounts` | 经账号生命周期流程应用 |
| `quota` | Collector 发布快照后由 Gateway 执行 |
| `deployment` | 由目标部署流程应用 |

## 常用设置

- 新 Key 默认前缀为 `ccpa_`，仅影响新建或轮换；已有 Key 不改写。
- 客户端 Key 环境变量默认为 `CCPA_API_KEY`；已保存的名称优先。
- 使用中心登录有效期为 1–12 小时，可用小时、天和小数显示，接口保存整数秒。
- 会话亲和默认 1 小时，范围 30 秒至 30 天，支持秒、分钟、小时、天显示。
- 账号自动切换支持 `off`、`active`。

### 最高推理强度

入口为“请求与账号 → 请求策略 → 最高推理强度”，配置键为 `gateway.max_reasoning_effort`，默认“不限制”。选择上限后，Gateway 在发送给 CPA 前，只降低用户显式指定且高于上限的等级。

等级按 `none < minimal < low < medium < high < xhigh < max < ultra` 比较。例如上限为 `xhigh` 时：

| 用户请求 | 转发值 |
| --- | --- |
| `max`、`ultra` | `xhigh` |
| `xhigh`、`high`、`medium`、`low`、`minimal`、`none` | 原值 |
| 未指定、`auto`、未知等级 | 原值 |

支持 Responses 的 `reasoning.effort`、Chat Completions 的 `reasoning_effort`，以及 CPA 的显式等级模型后缀（如 `model(ultra)`）。数值 Token 预算不转换；该设置也不会替用户补默认等级或推断模型是否支持某个等级。匹配已知等级时忽略大小写及首尾空格。

保存成功表示配置已写入控制库，并已等待 Gateway 加载新的鉴权快照。无需重启账号容器；后续 HTTP 请求和已有 Responses WebSocket 连接中的下一条 `response.create` 使用新上限，正在生成的响应不受影响。保存失败会尝试恢复旧配置并重新下发。选择“不限制”可恢复原始等级透传。

该策略在本项目 Gateway 执行，不需要修改 CLIProxyAPI 源码，也不属于 CPA 容器 YAML。直接访问 CPA 容器会绕过此策略。Responses WebSocket 的消息格式遵循[官方协议](https://developers.openai.com/api/docs/guides/websocket-mode)。

启用上限后，匹配的 HTTP 请求要求 JSON 对象，支持未压缩或 gzip，解压后最多 64 MiB；无效 JSON、重复顶层字段或重复 `reasoning` 子字段会被拒绝。Responses WebSocket 单条消息最多 64 MiB。其他 API、响应内容、模型倍率和历史用量不因本设置改写。

### 插件与版本检查

入口为“CPA 容器 → Codex Ticket 插件”。开关、模型、采票与注入、目标版本、自动检查和账号安装列表在同一页面维护；缓存与重试参数默认折叠在高级设置中。账号表格中的勾选框编辑适用范围，与其他配置共用保存栏；存在未保存修改时禁止安装。任务结果显示在对应账号行下方，原始诊断输出默认折叠。旧 `section=software` 链接继续打开此页，字段深链接仍可定位高级设置。CLIProxyAPI 的发布信息和自动检查开关移到“端口与镜像”；检查间隔仍是两个组件共用的既有设置。

- 自动检查默认每 6 小时执行一次，由持有写入租约的 Admin 调度，关闭网页后仍然运行。`software.cpa_auto_check`、`software.plugin_auto_check` 可分别关闭；`software.check_interval_hours` 范围为 1–168 小时。检查只读取发布元数据，不拉镜像、不安装插件、不调用模型。失败保留上次成功结果并显示失败状态。
- 先在“Codex Ticket 插件”账号表格勾选适用账号并设置模型，保存后在同一行安装或升级。账号选择仍持久化为 `plugins.codex_ticket.accounts`；查询刷新和筛选不会覆盖未保存选择，暂时不在账号列表中的已选 ID 保留并提供显式移除操作。仅允许处理已启用且运行中的账号，停止账号不会被启动。镜像需提供原生插件接口；当前支持 linux/amd64 glibc。
- 插件默认关闭，采票与注入分别由 `enabled`、`harvest_enabled`、`inject_enabled` 控制。这些键均位于 `plugins.codex_ticket.` 下。`proxy_source=custom` 使用独立的 Ticket 专用代理地址，不改变账号业务请求代理；`account` 复用账号已有代理。专用地址支持 HTTP、HTTPS、SOCKS5、SOCKS5h 及认证，加密保存，接口不回显，留空保留。未配置代理时不能启用所选账号的采票或注入，不会回退为直连。
- 默认安装上游原版 `v0.2.0`，下载原始发布包并校验 SHA256，不再构建或内置直连补丁版。旧目标版本迁移到 `v0.2.0`；旧直连配置改为专用代理模式并暂停采票和注入，等待用户配置。已安装版本继续保留，必须手动安装原版；停止账号不会被启动。来源与接入说明见 [插件说明](../plugins/codex-ticket/README.md)。
- `version` 是待安装版本，修改后不会自动升级。安装时校验摘要，并在目标账号的精确镜像中执行无凭据、无网络的隔离加载检查；通过后等待请求结束并重启该账号 CPA，可能短暂中断。失败尝试恢复旧配置。已安装版本固定在运行状态中，Control 升级不会自动替换它。
- TTL、提前刷新、扫描间隔、超时和失败退避均可配置。并发固定为每个 CPA 1 个；客户端已有 turn state 不覆盖。安装阶段暂停采票和注入，并在 `commercial-mode` 已随进程启动后再启用。

该插件仅处理 HTTP/SSE。缓存按实际凭据与模型隔离，重启或重新配置后丢失；WebSocket 不受插件处理。采到 292 字符状态只代表候选状态，不证明模型质量恢复。后台采票会额外消耗上游请求，建议从单账号、单模型开始验证。

### 系统时区

`system.timezone` 统一控制页面时间、自然日/自然周、趋势与通知，默认 `Asia/Shanghai`。修改后 Collector 重启并重新归集周用量，原始时间戳不改写。

旧配置按系统、额度、通知时区的顺序迁入此键；原额度与通知时区不同的环境，应核对新发送时间。宿主机时区不变，容器使用 UTC，旧 `CPA_TIMEZONE` 不再生效。

### 额度与倍率

“活跃用户统计窗口”控制账号列表、Usage、自动切换刷新和通知中的滚动去重用户统计，单位为秒，默认 `900`（15 分钟），可配置为 60–86400 秒。修改后后续读取立即使用新窗口。

“额度”集中设置用户额度、官方额度查询和用量维护；模型倍率、推理倍率分别管理。倍率大于 1 时显示“高倍率”标记。

加权 Token 在新事件采集时按“模型倍率 × 推理强度倍率”写入，历史记录不重算。`gpt-6-astra` 默认 4 倍，其他已知模型及未匹配模型默认 1 倍。模型字段为空时才回退到 alias，匹配忽略大小写和首尾空格。

“保留修改后的额度”默认关闭，下周恢复组织默认额度；开启后保留个人额度。两种模式下周用量重新累计，临时追加额度在换周后失效。

### 企业微信通知

Webhook 独立保存，已保存地址仅展示 key 末四位；更换时输入框为空，清除地址会关闭通知。

通知 Worker 随部署启动；开关开启且 Webhook 已配置才自动发送。页面分别显示调度心跳、发送结果和下次发送时间。心跳超过 3 分钟未更新时隐藏下次发送时间；手动发送成功不代表调度正常。

报告包含完整统计时间、阈值，以及账号总数、配置窗口内活跃账号、正常/预警/耗尽/数据不可用/已停用数量。所有通知头部均展示完整使用中心地址；未设置公开应用地址时显示“未配置”。时间按系统时区转换，显示为 `YYYY-MM-DD HH:mm:ss`，不附加时区字样。

账号明细统一使用表格，列为账号、周额度已用、配置窗口内用户、剩余重置次数和下次周期重置。只使用账号常规周额度，不包含附加额度窗口或套餐分布。按当前周额度已用百分比从小到大排序，同值按账号名称自然排序，数据不可用的账号显示 `—` 并排在最后。状态同时覆盖已发布的账号容量结果：已停用 `⏸️`、服务停止 `⛔`、未授权或凭据不可用 `🔐`、额度过期/不可用 `⚪`、上游不允许 `🔴`、额度预留 `🟠`；这些非正常状态不会用旧额度覆盖，也不参与额度预警、耗尽、恢复和周期重置判断。

预警、耗尽、恢复和周期重置使用同一表格，单账号也保留完整列，并增加“变化”列展示事件及已知的前后用量。预警、耗尽和恢复事件仅展示本次涉及账号；周期重置事件确认后发送全量账号表。定时报告合并事件时仍保留全量汇总。通道测试使用通知类型和状态两列表格。

“下次周期重置”表示常规周额度窗口的重置时间；仅用量下降不判定为周期重置。定时漏发超过补发窗口不自动补发。单条消息上限为 4096 字节，超限报错。

Telegram 项目发布公告通过 GitHub Actions Secrets [单独配置](telegram-release.md)。

## 开发约定

接口以 [OpenAPI](../api/openapi.yaml) 为准。配置和加密秘密存于控制库，用量与会话存于用量库；生成的账号配置和 Gateway 快照不是人工配置入口。

完整凭据不进入 URL、持久化浏览器存储或普通查询缓存。一次性凭据关闭弹窗后清理；`/site-config.json` 只输出公开品牌、允许的邮箱域和客户端导出字段。

页面结构见 [ConfigurationPage](../frontend/src/ui/ConfigurationPage.tsx)，布局见[配置样式](../frontend/src/ui/configuration-page.css)和[控件宽度](../frontend/src/ui/configuration-layout.ts)。修改接口时同步生成类型、前后端实现、测试与 Preview fixture；验证流程见[开发指南](development.md)。

## 界面与通知语言

页面默认英文，可通过语言选择器切换简体中文。配置中心的 `system.language` 控制定时通知、额度预警、手动报告与通知测试的语言，默认为 `en`，也可保存为 `zh-CN`。报表下载跟随页面所选语言；业务时区仍由 `system.timezone` 单独控制。详见[多语言设计](internationalization.md)。
