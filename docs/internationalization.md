# 多语言与英文默认版本

页面与应用接口默认使用英文，支持切换简体中文。页面语言不改变业务时区、额度周期、账号身份或已保存的配置值。模型 API 的上游响应、用户输入和原始日志保持原文。

## 方案选择与原方案对比

| 方面 | 原方案 | 当前实现 |
| --- | --- | --- |
| 翻译依据 | 中文原句作为前端键；对后端句子做正则匹配 | 前后端各自维护固定消息 ID，修改措辞不改变 ID |
| 接口语言 | 后端固定返回中文，浏览器补翻译 | `Accept-Language` 按请求协商；省略时英文 |
| 缓存与并发 | 文案与共享数据混合 | 请求上下文携带语言；展示时复制共享额度数据 |
| 错误处理 | 通用错误码与中文 message | 保留 code/type/message，增加可选 message_key/message_params |
| 配置与任务身份 | 分组名称、中文任务名参与判断 | 配置分组 id、字段 key、任务 action 保持固定 |
| 导出与通知 | 固定中文 | XLSX 跟随请求语言；后台通知使用 system.language |
| 验证 | 页面文案检查 | 目录/参数校验、HTTP 契约、并发隔离、双语报表与通知、浏览器矩阵 |

后端使用 **go-i18n v2** 管理目录、命名参数和 CLDR 单复数规则；HTTP 协商使用 `golang.org/x/text/language`。前端保留现有按入口加载的轻量目录，避免为了中英切换引入另一套全局状态。两端的文案由各自所属模块维护，前端直接展示接口生成的文本。

## 语言选择

浏览器按以下顺序选择语言：有效的 `?lang=` 参数、`cpa-ui-language` 主机 Cookie、同名 localStorage、英文。可选值为 `en` 和 `zh-CN`。切换会重新载入当前页面，保留路径、查询参数、片段、登录态与主题；未保存表单需要先保存。

所有公共 API 客户端请求（包括二进制下载）发送选中的 `Accept-Language`。后端支持质量权重，例如 `fr, zh-CN;q=0.8, en;q=0.5` 选择中文；`q=0` 的语言不参与选择。英语地域标签归为英文，中文地域/文字标签归为简体中文；这不表示提供繁体中文翻译。不支持、无效或过长的请求头回退英文。

应用接口返回 `Content-Language` 和 `Vary: Accept-Language`。`Vary` 保留已有的其他维度；现有认证、CSRF、缓存控制和下载权限仍由原有代码负责。

## 消息与数据边界

后端目录位于 [`internal/i18n/catalog/`](../internal/i18n/catalog/)，HTTP 边界位于 [`internal/httpi18n/`](../internal/httpi18n/)。服务校验返回带 ID 的消息，直到 HTTP 响应时才渲染。`WithCause` 保留 `errors.Is` 的错误链。

例如，无效布尔配置返回既有 `invalid_request` 错误码，同时附带稳定消息 ID：

```json
{
  "error": {
    "code": "invalid_request",
    "type": "request_error",
    "message": "Enable default upstream proxy must be a boolean",
    "message_key": "admin.must_be_a_boolean",
    "message_params": {
      "Field": { "message_key": "admin.enable_default_upstream_proxy" }
    }
  }
}
```

客户端根据 `code` 和业务字段处理状态，不能解析 `message`。消息参数不会再次作为模板执行。现有错误信封保持兼容，没有为了采用 RFC 9457 而强制改成另一种 JSON 结构。

HTTP 展示器只处理显式消息对象、实现展示接口的类型及容器中的这些对象。它不扫描任意字符串，不自动翻译用户姓名、产品名、模型名、代理信息、密钥、原始诊断输出或第三方返回内容。账号状态按稳定业务状态生成；共享额度快照通过副本展示。配置分组 `id`、字段 `key`、单位 `unit_code`、选项 `value` 与语言无关，旧中文分组链接仍有显式兼容映射。

前端目录位于 [`frontend/src/i18n/`](../frontend/src/i18n/)，英文与中文使用相同的固定 ID。公共词条随页面外壳加载，Admin、Usage 词条随对应模块加载。新增文案应使用完整句子；现有前端插值使用 `{0}` 等占位符，后端使用 `{{.Count}}` 等命名参数。需要复杂复数或语法变化时，扩展对应目录格式，避免在调用处拼接词尾。

## 固定英文的任务输出

管理员触发的运行时任务（镜像拉取与更新、服务启停、OAuth 设备登录、健康检查、路由校验等）的输出正文固定使用英文，不跟随 `Accept-Language`，也不跟随 `system.language`。输出是逐行日志，既要供前端结构化解析，也要在排障时与容器日志逐字比对，因此按机器可读原文处理，与用户内容、上游响应同级。这条边界是有意约定，不是遗漏。

任务**名称**仍按请求语言渲染（`internal/admin/runtime.go` 经 `Job.WithLanguage` 转换），所以中文管理员看到「中文任务名 + 英文日志正文」属于预期结果。`runtimeops.*` 的中英文条目都保留在 [`internal/i18n/catalog/`](../internal/i18n/catalog/) 中；如果以后要让正文跟随语言，需要在任务提交时捕获语言，并同步修改前端解析约定——[`ImageUpdateTaskReport.tsx`](../frontend/src/ui/components/ImageUpdateTaskReport.tsx) 目前同时接受中英两种行首，正是为这种切换预留的。

前端解析该输出后，结构化字段（账号、镜像、状态、计数）用前端目录重新渲染为本地语言；无法结构化的行、通知行和跳过原因按原文展示，这些位置会显示英文。

## 固定英文的界面上层标签

页面标题上方的大写拉丁标签（`section-kicker`、`eyebrow`、`native-kicker` 等）固定使用英文，不随语言切换。它们与任务输出一样是既定边界，不是遗漏：每个标签的正下方都紧跟一个已本地化的标题或说明，中文读者不会因此丢失信息；`App.tsx`、`configuration-layout.ts` 中同一语句里的 `title`/`description` 已经本地化，只有标签保持英文。

前端目录中不存在这些标签的条目。若要本地化它们，需要同时更新全部视觉基线与对应的 Playwright 快照，属于独立改动。

## 报表与后台通知

管理周报跟随下载请求的语言，表名、标题、说明、状态和文件名一同切换。图表公式引用本次工作簿的表名；Token 保持数值单元格，业务日期仍按 `system.timezone` 计算。用户自填名称不翻译。

配置中心的 `system.language` 设置用于后台通知，默认 `en`，可设为 `zh-CN`，即时生效。定时报告、额度预警、手动报告和通道测试均使用该设置；手动发送操作在页面上的成功/失败提示仍使用请求语言。通知保留原有排序、去重、事件范围、时区和 4096 字节限制。

新增设置沿用现有 settings 存储，无需数据库迁移或重写历史记录。部署后若希望继续接收中文通知，应将该设置保存为 `zh-CN`。

通知状态页的「最近错误」按请求语言渲染。落库时同时保存稳定消息 ID 与参数（`last_error_message`），并保留脱敏后的英文诊断文本（`last_error`）用于日志和排障；参数只记录可持久化的标量，嵌套消息与错误在记录时转为脱敏文本。缺少 `last_error_message` 的历史记录回退显示该诊断文本。手动发送失败的接口提示同样按请求语言返回，响应中不出现 Webhook 密钥。

## 验证与后续扩展

运行 `make -f scripts/build.mk verify` 与 `npm --prefix frontend run test:e2e`。重点回归包括：

- 两个目录的 ID 与参数一致、静态引用完整、默认英文及单复数；
- HTTP 默认语言、中文校验提示、错误元数据与不变的业务值；
- 并发语言请求不修改共享额度快照或消息对象；
- 两种语言的 XLSX 数值和图表引用，以及通知语言与状态流转；
- 浏览器切换、跨入口偏好、主题、移动端布局与英文残留检查。

浏览器预览使用 `testdata/preview/` 的中文样例及 `en/` 的英文样例，按请求语言返回。它验证页面集成；实际 Admin/Portal 处理器由 Go HTTP 测试覆盖。生产镜像、部署与真实环境验收另行进行。

增加第三种语言时，需要补全前后端目录、语言选择与协商列表、UI 组件库 locale，以及报表/通知测试。长文本、复杂语法、RTL 布局和翻译审核需要作为该语言的验收项；仅增加下拉选项不足以声明支持。

参考：RFC 9110（Accept-Language）、RFC 9457（错误详情不应作为机器协议解析）以及 go-i18n 项目文档。
